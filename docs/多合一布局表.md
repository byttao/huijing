# 多合一布局表

由 `src-tauri/src/grid.rs` 计算（单元测试 `print_layout_table` 生成：`cargo test print_layout_table -- --ignored --nocapture`）。

规则（第三轮起）：

- **所选比例就是整张图的比例**：实际请求、实际出图都用它，不再反推合成比例。多合一只是把这张图按宫格**等分**拆切（检测并裁掉分隔线），不再按目标比例居中裁切。
- 每格比例 = (a/cols):(b/rows) = (a·rows):(b·cols)，约分后显示。
- 4 张固定 2×2（每张比例与整张相同）。2 张、3 张可在横排（N×1）/ 竖排（1×N）间切换；两种排法下每格与整张的比例差距相同（都是 N 倍），所以默认取「每格更接近方形」的那种：横图并排、竖图上下叠；方图与自动比例默认横排。
- 比例为「自动」时也可以多合一，每张比例取决于实际出图。GPT 选 GIF / SVG 输出时不能多合一（无法拆切）。
- 「拆切后放大」（设置，默认开）：每张用 Lanczos3 等比放大，使长边等于整张图的长边（以下载到的合成图为准）；Nano「合图使用更高一档分辨率」时，以原档位整张图的长边为准（如 1K 选 4 张用 2K 请求，切出来就是原生 1K，不再放大）。
- 尺寸为估算（界面标「约」）：GPT 实际输出约 1.57MP（1:1 实测 1254×1254）；Nano 用 Gemini 3 的 1K 尺寸表（实测 4:3 = 1200×896、16:9 = 1376×768），2K / 4K 依次翻倍。下表是 1K 档。

格式：`布局 每张比例（约尺寸）`。

## 拆切

按宫格等分；在每条格线附近 ±4% 的窄带里：

1. 先找分隔线：整列 / 整行近似纯色（亮度极差 ≤ 24）的一簇细线，裁掉；连到窄带边缘的纯色区（大片天空、纯色背景）不算分隔线。
2. 没有分隔线时找内容接缝：相邻两行 / 列 RGB 平均差最大、且 ≥ 12 并 ≥ 带内中位数 3 倍的位置，在那里切。
3. 都没有时按等分位置切；内部边再内缩 0.4%。

结论：两个模型都会按要求的排法画、不画边框和文字；但格线不一定精确落在等分位置（实测最大偏 10 像素 / 约 1.8% 格高），所以拆切必须做接缝检测，不能只按几何等分。
